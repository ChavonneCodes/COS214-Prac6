 CWorkflowActionThis is the Command participant. Every action performed on a work item is an object that can run itself (execute), reverse itself (undo) and describe itself (getDescription, getInstanceId). WorkflowEngine::submit is the invoker: it runs the command and, only if it succeeded, hands it to the HistoryManager so it can be undone. The receiver is the WorkItem, which passes the request on to its current state

 CWorkItemStateThis is the State participant for a work item's life cycle. Every action a work item can be asked to perform (assign, start, complete, reject, cancel, escalate, fail, makeAvailable) is a virtual method that refuses by default: it prints "Invalid State Transition" and returns false. Each concrete state overrides only the actions it allows, so the legal transitions are defined by which methods a state overrides and not by conditionals in WorkItem. The class also declares the protected helpers (transition, bind, release, finish) through which a state changes the item's state, owner and workload, and the clone() used to save snapshots for the Memento
 CAssignedStateConcreteState for a work item that has an owner but has not been started. It allows start (moves to InProgressState), reject (the owner declines; moves to RejectedState and the owner is kept), escalate (the owner is released; moves to EscalatedState) and cancel (moves to CancelledState, ending the owner's workload but keeping them on record)
 CAvailableStateConcreteState for a work item that has been released and is waiting for an owner. It allows assign (binds the participant, counts the item in their workload and moves to AssignedState), escalate (moves to EscalatedState) and cancel (moves to CancelledState). assign is refused when no participant is given
 CCancelledStateConcreteState for a work item that was abandoned before it finished. It is a final state: it overrides no actions, so every action is refused. Any previous owner stays on record, but the item no longer counts towards their workload
 CCompletedStateConcreteState for a work item that has finished successfully. It is a final state: it overrides no actions, so every action is refused. The owner stays on record, but the item no longer counts towards their workload
 CCreatedStateConcreteState for a work item that exists in a running workflow but has not been released yet. It allows makeAvailable (moves to AvailableState) and cancel (moves to CancelledState); every other action is refused. A created item has no owner, so cancelling it changes nobody's workload
 CEscalatedStateConcreteState for a work item that has been handed over for someone else to pick up, for example after a timeout. The previous owner has been released. It allows assign (a new owner takes it; moves to AssignedState) and cancel (moves to CancelledState); every other action is refused
 CFailedStateConcreteState for a work item whose work went wrong while it was in progress. It allows makeAvailable (a retry; moves back to AvailableState) and cancel (moves to CancelledState); every other action is refused. The owner is kept, so a retry can go back to the same person
 CInProgressStateConcreteState for a work item that its owner is currently working on. It allows complete (moves to CompletedState, ending the owner's workload but keeping them on record), fail (moves to FailedState and the owner is kept so they can retry), escalate (the owner is released; moves to EscalatedState) and cancel (moves to CancelledState)
 CRejectedStateConcreteState for a work item whose assigned owner declined it. It allows makeAvailable (offers the item again; moves to AvailableState) and cancel (moves to CancelledState); every other action is refused. This is a task- level state meaning "declined by the assignee", not an approval outcome, which is carried by routing
